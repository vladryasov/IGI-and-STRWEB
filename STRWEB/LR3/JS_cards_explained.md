## Булевы операции (`&&`, `||`, присваивание)
- Приоритет: `&&` выше `||`; присваивание (`=`) ещё ниже. Выражение вычисляется слева направо с учётом приоритета.
- Короткое замыкание: `||` останавливается на первом truthy и возвращает его; `&&` останавливается на первом falsy и возвращает его. Возвращаются сами значения, а не bool.
- Карточка 1: `0 || 1 && 2 || x = 8` → сначала `1 && 2` = `2`; `0 || 2` возвращает `2`, до `x = 8` дело не доходит, `x` остаётся `undefined`.
- Карточка 2: `1 || 2 && 5 || 0` → первый операнд уже truthy, поэтому всё дальше не исполняется, результат `1`, переменная не меняется.
- Карточка 3: `true || (a = 1)` → правая часть не вычисляется, `a` не присваивается, остаётся `undefined`.
- Карточка 4: `2 && 1 && null && undefined` → `&&` ищет первый falsy; `null` встречается первым и возвращается.
- Почему так: `||` и `&&` работают с любыми значениями, не приводя их к bool до возврата. Truthy/falsy: falsy — `false`, `0`, `""`, `null`, `undefined`, `NaN`. Всё остальное truthy.
- Похожие случаи:
  - `0 && (x = 5)` → `0` (короткое замыкание, `x` не тронут).
  - `"" || "fallback"` → `"fallback"`.
  - `a && b || c` при `a` truthy и `b` falsy вернёт `c` (из-за приоритета эквивалентно `(a && b) || c`).
  - `x || (x = 10)` при `x = 0` присвоит `10`, при `x = 5` — не тронет.

## Оператор запятая, арифметика, строки
- Запятая имеет низкий приоритет и всегда возвращает результат последнего операнда, все предыдущие просто вычисляются и отбрасываются.
  - `(1,5-1,2) * 2` → в скобках последним остаётся `2`, итог `4`.
  - `(1,5+1,2) * 2` → аналогично, итог `4`.
  - `(1, 2 + 1) * 2` → последним остаётся `3`, итог `6`.
- Приведение к числу в арифметике: `null` → `0`; `undefined` → `NaN`; пустой массив `[]` в сложении со строкой → `""`.
- `null * 32` → `0 * 32 = 0`; то же при присваивании в переменную.
- `[] + false - null + true`: `[]` → `""`; `"" + false` → `"false"` (строка); `"false" - null` → `NaN - 0` → `NaN`; `NaN + true` → `NaN`.
- `true + false` → `1 + 0 = 1` (булевы приводятся к числам).
- Постинкремент: `x+++1` парсится как `(x++) + 1`; сначала выдаёт старое значение `x`, затем увеличивает `x`. Если `x = 5`: выражение даёт `6`, `x` становится `6`; следующий `x++` вернёт `6`, затем `x` станет `7`.
- Сравнение строк лексикографическое по кодовым точкам: `"груша" > "яблоко"` → `'г' < 'я'`, результат `false`.
- Вызов метода через индекс: `10e-1["toString"](2)` → `10e-1` это `1`; `toString(2)` от числа `1` даёт строку `"1"`.
- Почему так: арифметические операторы требуют чисел; перед вычислением идёт приведение к Number. При `+` с операндами-строками приоритет у конкатенации, но как только один операнд становится числом, идёт численное сложение.
- Похожие случаи:
  - `undefined + 1` → `NaN`; `undefined - 1` → `NaN`.
  - `[] + []` → `""` (пустые строки); `[] - []` → `0` (оба → 0).
  - `{} + 1` в начале строки может парситься как блок кода (результат `1`) или как объект, тогда `"[object Object]" + 1` → строка; зависит от контекста.
  - `"2" * "3"` → `6` (строки приводятся к числам), `"2" + "3"` → `"23"` (конкатенация).
  - `+"5"` → `5`, `+"5px"` → `NaN`.

## Новые свойства у значений
- Литерал объекта требует пары `ключ: значение`; запись `{"Hello"}` синтаксически неверна.
- Обычные объекты можно расширять: `{tr: "Hello"}.something = 5` сохраняет свойство, чтение вернёт `5`.
- Примитивы оборачиваются временным объектом для доступа к методам; добавленные свойства не сохраняются. Поэтому `"Hello World".something = 5` при чтении даст `undefined`.
- Почему так: примитивы (string, number, boolean, symbol, bigint, null, undefined) неизменяемы; для доступа к методам создаётся временный wrapper-объект, который сразу выбрасывается.
- Похожие случаи:
  - `let n = 10; n.foo = 1; console.log(n.foo);` → `undefined`.
  - Для `new String("Hi")` свойство сохранится, потому что это объект-обёртка, но такой код почти всегда лишний.

## Разное
- `new Date()` возвращает объект даты; при выводе вызывается преобразование в строку с текущим временем (локаль/часовой пояс влияют на формат).
- Строки индексируются как массивоподобные: `"156"[0]` → `"1"`, `"1"[0]` → `"1"`.
- Похожие случаи:
  - `date - 0` → число (timestamp в мс), потому что `Date` при приведении к числу использует `valueOf`.
  - `"abc".length` доступен, но попытка присвоить `length` не изменит строку — она неизменяема.

## `parseInt`
- Парсит с начала строки до первого невалидного символа. Если первый символ не число/знак, результат `NaN`.
- `parseInt("$1.2")` → сразу `NaN` (первый символ `$`).
- `parseInt("0 минут")` → читает `0`, дальше останавливается → `0`.
- `parseInt("1px")` → читает `1`, дальше `px` обрезается → `1`.
- Почему так: `parseInt` читает посимвольно, пока формат подходит целому числу. Без явного основания может считать числа с ведущим `0` восьмеричными в старых движках, поэтому безопаснее указывать основание.
- Похожие случаи:
  - `parseInt("08")` в старых средах мог дать `0`; с явным основанием `parseInt("08", 10)` → `8`.
  - `parseInt("0x10")` → `16` (префикс `0x` даёт 16-ричное).
  - Для дробей нужно `parseFloat("1.23px")` → `1.23`.

## Массивы
- `new Array(3)` создаёт массив длины 3 с «дырами» (empty slots). Элемент `b[0]` при чтении даёт `undefined`, поэтому `1 + undefined` → `NaN`.
- Сравнение массивов идёт по ссылкам: два одинаковых литерала — разные объекты, `false`.
- `a[a.length] = ...` кладёт в конец; после двух присваиваний длина `2`.
- `slice(1,3)` берёт элементы с индекса 1 включительно по 3 не включительно → `[20, 30]`.
- Пропуск индексов создаёт разрежённый массив; `delete a[10]` убирает значение, но не уменьшает `length`, поэтому после `a[10] = 100; delete a[10]` длина остаётся `11`.
- `join` пропускает дыры: `[1,,,,5].join("+")` → `"1++++5"`.
- Почему так: «дыры» и `undefined` ведут себя по-разному в некоторых методах; `map` пропускает дыры, `forEach` тоже, а индексация возвращает `undefined`.
- Похожие случаи:
  - `Array(3).map((_, i) => i)` → `[ , , ]` (не заполнит, потому что дыры пропущены); `Array.from({length:3}, (_, i) => i)` → `[0,1,2]`.
  - `delete a[0]; a.length` остаётся прежней; `a.splice(0,1)` сдвигает и уменьшает длину.
  - Присвоение `a.length = 1` обрезает массив; `a.length = 100` добавляет дыры.

## Приведение типов и сложение с объектами
- При `+` с объектом движок запрашивает примитив: сначала `valueOf`, затем `toString` (если не число, обычно строка).
- `{toString(){return '1'}}`: `1 + '1'` → строка `"11"`, затем `"11" + 1` → `"111"`.
- `{toString(){return 3}}`: возвращает число → `1 + 3 + 1` → `5`. Аналогично в примере с тремя переменными `a + b + c` где `b` — объект со `toString → 3`.
- `prompt` возвращает строку; `"5" + 1` → конкатенация `"51"`. Чтобы получить `6`, нужно `Number(a)` или унарный `+a`.
- `concat` возвращает новый массив, аргументы-элементы раскрываются: `[1].concat(2,3)` → `[1,2,3]`; передача массива без спреда даёт вложение: `[1].concat([2,3])` → `[1,[2,3]]`.
- Почему так: операция `+` со строкой переключает режим «string», и все последующие операнды конкатенируются; без строки пытается привести к числу. Алгоритм ToPrimitive с hint "default" предпочитает `valueOf` у числовых объектов.
- Похожие случаи:
  - `1 + {valueOf(){return 4}}` → `5`.
  - `1 + {}` → `1[object Object]` (строка), потому что объект не дал числового примитива.
  - `"" + 1 + 2` → `"12"`; `1 + 2 + ""` → `"3"` (сначала числа, потом строка).
  - Унарный плюс/минус всегда приводит к числу: `+"10"` → `10`, `-"10"` → `-10`.

## Необъявленная (пока) переменная и `var`
- Объявления `var` поднимаются (hoisting), но инициализация остаётся на месте. До строки присваивания переменная существует со значением `undefined`.
- В `console.log(a + b + c)` до присваиваний все три — `undefined`; арифметика с `undefined` → `NaN`. Позднейшие присваивания уже не влияют на выполненный лог.
- Почему так: поднятие касается только `var` и function declarations; `let/const` создают «временную мёртвую зону» и доступ до объявления приведёт к ReferenceError.
- Похожие случаи:
  - `console.log(x); let x = 1;` → ReferenceError (TDZ).
  - `f(); function f(){ console.log(1); }` → сработает благодаря hoisting функции.
  - `console.log(y); var y = 2;` → `undefined`, затем `y` станет `2`.
